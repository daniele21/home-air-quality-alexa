# Airwise mobile UX review — baseline 2026-11-02

## Scope and severity

Reviewed `dashboard.html`, `pollution.html`, `context.html` and local Python endpoints as static source. Original UI looks coherent on desktop but exhibits multiple mobile-first and data-viz weaknesses. P0 = task blocked, P1 = usability/accessibility, P2 = polish.

| Priority | Surface | Evidence | Proposed correction | Exit criterion |
| --- | --- | --- | --- | --- |
| P1 | Overview above-the-fold | Huge two-line marketing hero before measurements | Compact mobile analytical heading, reach data immediately | Main metric visible with minimal scrolling at 375px |
| P1 | Cross-page navigation | Overview link to pollution, pollution link to context, separate back links | Shared compact three-destination navigation mobile/desktop | Any of three pages reachable in one tap |
| P1 | Touch targets | `.step` 38px, `.arrow` 36px, `.pill` around 36px | 44px minimum targets incl segmented controls and delete | Minimum interaction bounds 44x44px |
| P1 | Mobile text and form | Multiple 10/11/12px labels and 13px fields | Primary controls at least 16px, secondary 12–14px | Readable at default zoom, mobile inputs don't autozoom |
| P1 | Data-viz chart interaction | Canvas uses only `onpointermove`; no keyboard/readable underlying table | Select/tap + accessible table or summary | Values accessible without hover |
| P1 | Heatmap | 24 columns in full width at small viewport | Container-only scrolling or mobile aggregates | No page-wide overflow, readable cells |
| P1 | Different data sources | Modelled outdoor and Alexa measurement shown close together | Distinct labels, dash/style as well as color, confidence notes | No accidental equivalence of models/sensors |
| P2 | Visual system | Three independently themed CSS files with hard-coded colors | Shared token names, coherent hierarchy | No conflicting dark-mode, selected-state logic |
| P2 | Empty/outdated data | External view empty until opt-in, import anchored to historic data | Explicit zero-state and last observation timestamp | Clear action and freshness context |
| P2 | Chart legibility | Dense lines with hover tooltip, tiny date labels | Responsive tick density, zoom-friendly summary | At 320px axis labels not clipped |

## Prioritized implementation passes

- Pass A: skills + `DESIGN.md` + mobile navigation/touch typography/heatmap containment; current ticket.
- Pass B: chart alternatives, richer handling of tap/keyboard exploration, simplify landing hierarchy.
- Pass C: synthetic-data screenshots at 320, 375, 390, 768, 1024, 1440; compare visual diffs; validate on real Mac without uploading private data.

## Verification boundaries

This review is source-based, **not a screenshot inspection**. Any automatic HTML/CSS source check is partial; only screenshot review/browser interaction validates clipping, hit-testing, readability and visible states. Don't mark Pass C complete until it has genuinely run.

## KPI hierarchy and mobile evidence-first correction (2026-11-02)

User critique: previous demo overstated KPI size. Confirmed source-level
problem: equal-weight secondary numbers and oversized KPI tiles hid the
main analytical chart. Geometric overflow checks had not tested vertical
information density; the first failed vertical audit found the Pollution
chart starting at 865px on a 320px phone.

Changes (design-direction → mobile-first → data-viz → visual-qa):
- Overview: shorter analytical title; only PM2.5 has a featured summary,
  with four smaller sensor controls in a horizontally scrollable rail.
- Pollution: mediana and P90 small supporting cards; episodes/coverage
  reduced to inline compact summaries; daily chart is prioritized.
- Context: three small paired-history metrics, comparison chart remains
  primary. The diary and opt-in outdoor semantics are preserved.
- Expanded Chrome audit to inspect actual computed numeral sizes,
  actual KPI card heights and first-chart vertical positions.
- A legacy 160px flex-basis initially prevented the newly compact
  Overview card from shrinking. Fixed that CSS conflict rather than
  accepting a "test passed" claim based on font size alone.

**Verified Chrome geometry, 320px phone viewport**:
- Overview: PM2.5 **28px / 85px-high** primary card, secondary **20px /
  87px-high**, first chart **698px** from top (was **785px** before
  the flex-basis correction), zero body overflow, zero undersized targets.
- Pollution: four summary numerals **21px** except subordinate inline
  figures **17px**; first chart **762px**, versus **865px** before
  the hierarchy redesign. No loss of anchor navigation.
- Context: comparison numerals **19px**, first chart **677px**.
- At 375/390px, Overview first chart begins at **640px**.

Final 18-viewport (3 pages × 320/375/390/768/1024/1440) Chrome
report: **PASS_LAYOUT**, private PNGs saved Mac-only,
https://github.com/daniele21/local-runner-infra/actions/runs/41435983281.
